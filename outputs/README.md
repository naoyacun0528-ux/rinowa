# outputs

ビルドのたびにここへ成果物を出します。バージョンごとにフォルダが増えます。

```
outputs/
└── 0.1.2/
    ├── echo-0.1.2-release.apk    配布用。専用の鍵で署名済み
    ├── echo-0.1.2-debug.apk      開発用
    ├── echo-0.1.2-source.zip     その時点のソース一式
    └── RELEASE-0.1.2.md          何が変わったかの説明
```

## バージョンの付け方

| 種類 | 上げ方 | 例 |
|---|---|---|
| 不具合修正・調整・小さな機能追加 | 3桁目 | `0.1.0` → `0.1.1` |
| まとまった新機能 | 2桁目 | `0.1.3` → `0.2.0` |

バージョンは `android/app/build.gradle.kts` の `versionName` が唯一の正で、
出力スクリプトはそこを読みます。上げ忘れると前のフォルダを上書きするので、
**作業のたびに先に上げてください**（Claude が上げます）。

## 出力のしかた

```bash
powershell -File C:\dev\echo\tools\release.ps1
```

端末は不要です。ビルドして APK とソース zip をこのフォルダへ置くだけです。
`RELEASE-<version>.md` は内容を説明する文章なので手で書きます。

**出力したら、毎回チャットにファイルそのものを添付すること。**
パスを書くだけでは受け渡したことになりません。

## APK について

**2種類出ます。**

| | applicationId | 用途 |
|---|---|---|
| release | `jp.echo.android` | **配布用。** 専用鍵で署名済み。R8 で圧縮され約 1.2MB |
| debug | `jp.echo.android.debug` | 開発用。ログが出る。約 11.6MB |

applicationId が違うので**同じ端末に両方入れられます。**

release の署名鍵は失うと更新を届けられなくなります。
バックアップ手順は [docs/SIGNING.md](../docs/SIGNING.md) を参照してください。

## 秘密ファイルの扱い

ソース zip は生成後に走査され、署名パスワード等が混入していた場合は
**zip を破棄して停止**します。除外リストは更新を忘れうるため、完成物そのものを検査しています。
