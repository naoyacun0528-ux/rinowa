# outputs

ビルドのたびにここへ成果物を出します。バージョンごとにフォルダが増えます。

```
outputs/
└── 0.1.1/
    ├── echo-0.1.1-debug.apk      端末に入れられるアプリ本体
    ├── echo-0.1.1-source.zip     その時点のソース一式
    └── RELEASE-0.1.1.md          何が変わったかの説明
```

## バージョンの付け方

| 種類 | 上げ方 | 例 |
|---|---|---|
| 不具合修正・調整・小さな機能追加 | 3桁目 | `0.1.0` → `0.1.1` |
| まとまった新機能 | 2桁目 | `0.1.3` → `0.2.0` |

バージョンは `android/app/build.gradle.kts` の `versionName` が唯一の正で、
出力スクリプトはそこを読みます。上げ忘れると前のフォルダを上書きするので、
**作業のたびに先に上げてください**（Claude が上げます）。

## 出力のしかた

```bash
powershell -File C:\dev\echo\tools\release.ps1
```

端末は不要です。ビルドして APK とソース zip をこのフォルダへ置くだけです。
`RELEASE-<version>.md` は内容を説明する文章なので手で書きます。

## APK について

現在出しているのは **debug ビルド** です。開発用の鍵で署名されているため、
そのまま端末に入れて動きますが、ストア配布には使えません。

配布用の release ビルドには署名鍵（keystore）が必要で、これは
**紛失すると同じアプリとして更新できなくなる**種類のものです。
作成と保管の方針は配布を現実に検討する段階で決めます（Prototype 2 以降）。
