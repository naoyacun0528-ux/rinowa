# Lowan 0.20.1 — 鍵の検証がひととおり揃いました

0.20.0 で入れた「安全性の確認」に、**鍵が変わったときの知らせ**と**確かめた印**を足し、
**古い一覧を見せていた不具合**を直しました。

## 1. 一覧が古かった（0.20.0 の不具合）

0.20.0 の実機確認で、**今日登録したはずの端末が一覧に出ませんでした**。

原因は単純でした。端末一覧を取りに行くのは `prepareRoom`、つまり**メッセージを送るとき
だけ**です。確認画面を開いても何も問い合わせず、最後に送ったときの記録を見せていました。

**確認の画面が古い事実を見せるのは、無いより悪い。** 開いたときに取りに行くようにしました。

実機で3台に増えました（今日 / 昨日 / 8月20日）。今日のぶんが出ています。

## 2. 鍵が変わったら知らせる（V-3）

前に見た相手の指紋を端末に覚えておき、開くたびに比べます。

- **端末が増えた** — 機種変更や再インストールで起きる。落ち着いた色で出す
- **同じ端末なのに指紋が変わった** — 普通に使っていて起きることではない。赤で出す

**機種変更と乗っ取りは、この端末からは同じに見えます。** 区別しようとせず、
変わったことだけを言って判断は利用者に返します。断定すると、外れたときに嘘になります。

初めて見る相手には警告を出しません。初回に警告を出すと、誰も読まなくなります。

**実機では未検証です。** 相手の端末構成が変わる機会が要ります。次に We2 のデータを
消すときが試し時です。

## 3. 確かめた印（V-5）

読み合わせて同じだったら「同じでした」を押します。「確かめました」に変わり、取り消せます。

**この端末の中だけの記録です。** サーバーにも相手にも送りません。指紋を読み合わせたのは
利用者本人なので、その判断を持つのも本人の端末でよい、という考えです。

## 4. クロスサイニング（V-4）は着手しません

FFI に `bootstrapCrossSigning()` はあり、運ぶ口を作れば技術的には通ります。

**問題は鍵の置き場所です。** クロスサイニングの秘密鍵が端末と一緒に消えると、
再インストールのたびに**別人の身元**が生まれ、相手には毎回「身元が変わりました」と
出ます。**いまより悪い。** 警告が日常になると、本物の警告も読まれなくなります。

置き場所としては、既にあるドライブ + 暗証番号のバックアップが自然です。ただしそれは
**バックアップの形式を変える**ということで、0.19.3 で実機検証を通したばかりのところに
手を入れます。数日かかる作業です。

**順番として、先に V-3 を実機で確かめます。** 鍵が変わったときの知らせが本当に出るかを
見ないまま、その上に身元の仕組みを積みません。
