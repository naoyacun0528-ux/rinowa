# Lowan 0.15.0 — E2EE の土台

**まだメッセージは暗号化されていません。** 土台を作って、実機で確かめる手段を付けた版です。

## 検証してください

**Direct Lab → 「E2EE の往復確認」→ 検証**

鍵を公開し、暗号化して、復号します。**相手の端末は要りません。**
最後の行が `round trip OK — 復号一致` なら通っています。

これが通ってから、実際のメッセージ経路を切り替えます。

## なぜ先に本番へ入れないか

暗号は鍵と権限ルールとメッセージ経路を同時に触ります。いきなり本番に入れて間違えると、
**読めないメッセージ**として現れます。**それは巻き戻せません** —— 平文はもう無く、鍵は違う。

なので最初の1回は、失敗しても1行のログで済む場所でやります。
Rinowa のときと同じ順序です。**実機で測ってから採用する。**

## 採用したもの

**`org.matrix.rustcomponents:crypto-android`（Apache-2.0）**

Olm と Megolm の Rust 実装で、Element が実運用しているものです。

| | |
|---|---|
| 費用 | **無償。**ロイヤリティなし |
| ビルド | 既製 AAR。**Rust ツールチェーン不要** |
| サイズ | **+18.85 MB／端末**（14.61 → 33.46 MB） |

**libsignal は使えません。** AGPL-3.0 で、**App Store の規約と衝突します**（VLC が
App Store から消えたのと同じ理由）。いちばん有名な選択肢が最初に落ちました。

**暗号は1行も書いていません。** ラチェットも鍵も署名も全部ライブラリのものです。
こちらが書いたのは、ライブラリが「これを送れ」と言うものを Firestore へ運ぶ層だけです。

## 権限ルールを足しました（38件 → 57件）

3つのコレクションで、**読める範囲が全部違います。**

| | 誰が読める | 誰が書ける |
|---|---|---|
| `cryptoDevices/` | **全員**（公開鍵なので） | 本人だけ |
| `oneTimeKeys/` | 全員（取って消す） | 置くのは本人だけ |
| `toDevice/` | **本人だけ** | 全員が投函できる |

`toDevice` は郵便受けです。**投函はできて、覗けるのは本人だけ。**

`cryptoDevices` を既存の `devices`（FCM トークン）と別にしたのが要点です。
片方は**読めなければ暗号化できない**もの、もう片方は**読まれたら他人の端末に通知を撃てる**もの。
性質が正反対なので、同じ文書に混ぜません。

### 既知の弱点も書いておきます

**ワンタイム鍵は誰でも消せます。** 枯渇させる嫌がらせが可能です。サーバが無い以上、
レート制限は書けません。Olm の fallback key がこれを吸収しますが、
根本的な対処は Prototype 2 の課題として残します。

## 配布を直しました

**ABI ごとに分割して、arm64 版を配ります。**

| | |
|---|---|
| release（arm64） | **33.5 MB** ← 配布 |
| release（4 ABI 全部） | 120 MB ← 手元に残すだけ |

暗号を入れて universal が 120 MB になったので、分けないと**それを落とすのは利用者**でした。

### 判定を一度間違えました

最初はこの universal の数字を見て「75 MB は払えない、採用しない」と書きました。
**分母が間違っていました。** universal APK は配布形態ではありません。
誰も経験しないコストを理由に機能を落とすところでした。

指摘は開発者本人からで、「LINE は 319 MB、33.51 MB が現状と見て判断」。
**その 33.51 MB は正確でした**（実測 33.46 MB）。

## 機種変更の履歴について（設計確定）

E2EE を入れると「ログインすれば全部戻る」は**成立しなくなります。**
新しい端末は鍵を持たないので復号できません。

**LINE も解決していません。** 実際、機種変で Letter Sealing により復元が壊れる現象があり、
出回っている対処法は「**バックアップ前に暗号をオフにする**」です。

Lowan の方針は **利用者自身の Google Drive（appDataFolder）+ PIN** に決めました。
**鍵は端末から出しません** —— 鍵まで預けたら、預け先が自社サーバから Google に
移っただけになります。使うスコープは Google の分類で **non-sensitive**、
必要な審査は basic のみ（動画提出もセキュリティ監査も不要）であることを確認済みです。

## 通話に穴が見つかりました（未修正）

通話は DTLS-SRTP で暗号化されていますが、**SDP のフィンガープリントが Firestore を
平文で通っています。** Firestore を書き換えられる者は、自分のフィンガープリントを
両側に配って**通話の中間に入れます。** 音声は暗号化されたまま、攻撃者との間で。

直し方は暗号を変えることではなく、**フィンガープリントを to-device 経路で送る**ことです。
メッセージの暗号化が動いてから着手します。
