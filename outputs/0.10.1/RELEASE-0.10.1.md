## 写真 — 判断を間違えていました

**0.10.0 で出していたのは、写真ではなく「写真が届くまでの仮置き」でした。**
そして本体のアップロードを作っていなかったので、**仮置きが最後まで仮置きのままでした。**

LINE と並べれば一目で分かることで、使い物にならないのはその通りです。
「段階1」と呼びましたが、**写真が永遠に届かない写真機能は段階1ではありません。**

### 直したこと

**本体が実際に届くようにしました。** Firestore に `media/{ハッシュ}` として置き、
受信側が取得して端末に保存します。スタンプが同じ方法で動いているので、実績のある経路です。

サーバー（XServer）を待たずに済ませたのは、**今日動くほうが正しいと判断した**からです。
アーキテクチャは何も変わりません — メッセージが運ぶのは ID だけ、ID は内容のハッシュ、
置き場所を知っているのは `MediaRepository` だけです。移すときはそこだけ差し替わります。

**ハッシュが一致しないバイト列は捨てます。** ID が検証そのものなので、
サーバーが正しいものを返したかどうかを信用する必要がありません。

### 大きさを LINE に合わせました

- 幅を**画面の 56%**（上限 240dp）に。前は本文と同じ幅で、縦写真が画面を占領していました
- **写真の本来の縦横比を使います。** 前は比率を 0.6〜1.8 に丸めて切り抜いていました。
  **撮った人が決めた構図を、こちらで勝手に変えていたことになります**
- 縦に長い写真は高さ 320dp で止めます

### 仮置きの扱い

ぼやけたプレビューは**本体が来るまでの足場**であって、成果物ではありません。
本体が届いたら差し替わります。**届いた後もぼやけたままなら、それは機能が失敗しています。**

## 通話 — 測った数字と、TURN の答え

### APK は 3.78 MB → 44.62 MB（全ABI合計）

WebRTC を入れて実測しました。**ABI 分割 / App Bundle なら1台あたり約 14 MB。**

必須機能とのことなので、これは受け入れる前提で進めます。
**ただし今の版では依存を外してあります** — 通話が未実装なのに、
写真の検証のたびに 40 MB 余計に落とすのは無駄なので。実装に入るとき戻します。

### 「TURN が無いと たまに動かない」への答え

**TURN は「要るか」ではなく「どれにするか」の問題です。** 必ず用意します。

| 案 | 費用 | 評価 |
|---|---|---|
| **Cloudflare の TURN** | 無料枠が大きい | **推奨。** 運用するサーバーが増えない |
| Tokyo の VPS で coturn | 月 600〜1000円 | 自前で持てる。乗り換え先として確保 |
| XServer で coturn | — | **不可。** 共有ホスティングでは常駐できない |

**どちらでも切り替えは設定1行**です（ICE サーバーの一覧を渡すだけ）。
まず無料枠で始め、費用か依存が問題になったら VPS に移します。

**重要な設計点**: TURN の認証情報は**短命なものをサーバーで発行**します。
APK に固定パスワードを埋めると、**取り出されて他人の帯域として使われます**。
`push.php` が既に Firebase の ID トークンを検証しているので、同じ場所で発行できます。

## まだ答えていないこと

**ビデオ通話の「その端末が対応している最高の圧縮で送る」案**と、
**将来のオリジナル画質**については、次で設計をまとめます。
先に写真の見え方を確認してください。

短く方向だけ:

- **圧縮方式は「両方の端末が対応しているもの」しか使えません**（WebRTC が交渉するので）。
  そして重要なのは**ハードウェアで符号化できるか**です。
  ソフトウェアで AV1 を回すと発熱と電池で破綻します。**実機で確かめてから決めます**
- **「オリジナル画質」と「元ファイル」は別物です。** 再エンコードして EXIF を落としつつ、
  解像度と画質は原寸のまま送れます。**位置情報を捨てる原則は維持できます**
- ただし原寸は 3〜15 MB あり、**Firestore には入りません**。
  そこが本当の保管場所を用意すべき地点です
