# Lowan 0.15.2

0.15.0 で報告された2件を直しました。**どちらも、僕が原因を隠す形で書いていたものです。**

## 1. 「暗号エンジンを開けませんでした」

### 直接の原因

**AAR に同梱されている `proguard.txt` が 0 バイトでした。**

このライブラリは JNA でネイティブコードに繋がっており、JNA は**クラスやフィールドを
実行時に名前で引きます。** R8 はそれを「使われている」と判断できないので、
release ビルドで削るか改名します。

削られても**ビルドは通り、起動もします。** 壊れるのは暗号エンジンを最初に開いた瞬間だけ。
debug ビルドでは R8 が走らないので再現しません。

keep ルールを追加しました。

### もっと悪かったこと

エラーが `runCatching { }.getOrNull()` に飲まれていて、
画面に出たのは「**開けませんでした**」の一行だけでした。**何が起きたのか誰にも分からない。**

**これは僕自身が「最悪の失敗の形」として何度も書いてきたものです。**
通話の応答が動かなかったとき、原因を突き止めるのに丸一回分かかった理由がまさにこれでした。

例外の内容をそのまま出すようにしました。次に失敗したときは、その行が原因を指します。

## 2. 停止を押すと「開始できませんでした ol1」

**バグです。2つ重なっていました。**

### なぜ「停止」で「開始」のエラーが出るのか

`stop()` は探索コルーチンを cancel します。すると中で `CancellationException` が上がり、
**`runCatching` がそれを普通の失敗として捕まえます。**

つまり「利用者が止めた」が「開始に失敗した」として報告されていました。
Kotlin のコルーチンで最も知られた落とし穴で、**`runCatching` を使った箇所ごとに
手で外す必要があります。**

### なぜ `ol1` なのか

**R8 がクラス名を難読化した結果です。** 例外の種類をクラス名から出していたので、
release ビルドでは意味のない記号になっていました。

**診断が一番必要な場所で、診断が消えていた**ことになります。

2つ直しました。例外のメッセージを先に読むようにし、例外クラスの名前は
難読化されないようにしました（`-keepnames class * extends java.lang.Throwable`）。
