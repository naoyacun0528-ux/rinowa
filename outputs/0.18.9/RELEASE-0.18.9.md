# Lowan 0.18.9

動画まわりの4点。0.18.8 の整理で見つかった重なりと、指摘のあった不足分です。

## 1. 再生中はビューアのボタンを出さない

削除・共有・保存の列と、プレイヤーの操作列（`0:05 / 0:05`・`1x`・シークバー）が同じ帯に
来ていて、ゴミ箱がシークバーの上に乗っていました。再生を始めたらビューアの列は引っ込み、
下はプレイヤーだけが使います。

この重なりは 0.18.7 の時点でありました。動画をページの中で再生するようにした時からで、
0.18.8 の整理で動かした場所ではありません。

## 2. ボタンの位置を下げた

9:16 の動画では、映像の下端にアイコンが軽くかぶっていました。下の余白を 18dp から
12dp に詰めて、6dp（およそ 1mm）下げています。映像の下に完全に出ました。

## 3. すりガラスが動画に追いつくようにした

再生ボタンの丸は裏の映像を写してぼかしています。これまでは 125ms ごと（毎秒8回）に
撮っていたので、映像が動いているのに中身が飛び飛びに遅れて付いてきていました。

TextureView は新しいフレームを描いたときに知らせてくれるので、**その時だけ撮る**ように
しました。動画のフレームと1対1になります。止まっている映像では1枚も撮りません。

media3 が付けている listener は外しません。外すと映像そのものが止まります（表示先の面を
管理しているのがその listener）。あいだに入って、通知をそのまま渡してから自分の分を
数えています。読み戻しがフレームより遅い端末では、待つあいだに来たフレームを飛ばして
最新だけを撮ります（遅れて古い絵を出すより、間引いて今を出すほうがよい）。

**実測**：再生中の連続4フレームで、ボタンの中の明るさが 3.6 → 4.4 → 10.2 と、映像の
変化（28.6 → 32.4 → 14.6）に合わせて動きました。再生が終わると両方とも変化 0.00 で
一致。映像が変わったときだけ、ボタンの中も変わっています。再生のなめらかさは変わりません。

## 4. 動画にも共有を出した

これまで動画は保存だけでした。共有シートは、まだ端末に無いファイルを待てないためです。

保存と同じように**先に本体を取り終えてから**シートを開くようにしました。取得中は
「準備しています…」と出ます。復号済みの本体をそのまま渡すことはしません。FileProvider に
見せているのは `cacheDir/share` だけで、そこに1本だけ写してから渡します。それ以外を
公開すると、受信済みの動画が全部外から取れることになります。

## 確認したこと

- コンパイル：エラー0・警告0、テスト66件すべて通過
- 実機（Pixel 10、release）
  - 動画のページに削除・**共有**・保存の3つが出る
  - 3つとも映像の下端より下にある（9:16 で確認）
  - 再生を始めると3つが消え、シークバーの帯が空く
  - 共有 →「準備しています…」→ `lowan-c36bca5f174b.mp4` の共有シート

## 残っている点

再生を始めると、そのページの削除・共有・保存は**閉じるか隣のページへ動くまで戻りません**。
「再生中は隠す」を選んだ結果ですが、動画は一度再生するとポスターの状態には戻らないので、
実際には「そのページでは以後出ない」という動きになります。

再生が終わったらポスター（再生ボタンの付いた静止画）に戻す、という直し方があります。
そうすれば3つのボタンも戻ります。どうするか決まっていないので、いまは触っていません。
