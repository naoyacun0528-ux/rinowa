# Lowan 0.17.1

## 一覧に本文が出ます。サーバには渡しません

`🔒 メッセージ` をやめました。**各端末が最新の1通を取って自分の鍵で復号し、
自分の一覧を作ります。** 通知でやっているのと同じ形です。

サーバに保存されるプレビューは**マーカーのまま**です。あそこは会話ドキュメントの中で、
**サーバが読める場所**なので、本文を書くと**各会話の最新1通が丸見え**になります
——たいてい一番大事な1通です。

復号できないときだけマーカーのまま残ります（鍵が未着、またはこの端末より前のメッセージ）。
**知らないことを知っているふりはしません。**

## 未読バッジが消えなかった件

**バグでした。**

スレッドを開くと `conversations/{id}/reads/{me}` に書きます。これは**サブコレクションの
文書**で、**会話ドキュメント自体は変わりません。** 一覧はその会話ドキュメントの変化で
作り直されるので、**読んだのにバッジが残っていました。**

「すべて既読」で消えたのは、あれがメモリ上の一覧を直接書き換えていたからです。
症状だけ消えて、原因は残っていました。

一覧に戻るたびに未読とプレビューを計算し直すようにしました。スレッドを開いている間
一覧はコンポジションから外れるので、戻った時点で確実に再計算が走ります。

## Pixel で通知が2つ出た件 — アプリのバグではありません

Pixel に **Lowan が2つ**入っていました。

| | |
|---|---|
| `blog.nextlab.echo` | 0.16.3（新） |
| `blog.nextlab.echo.debug` | **0.15.3-debug（古い）** |

古い debug 版は push の中身をそのまま出すので **「新しいメッセージ」**、
新しい release 版は復号してから出すので**少し遅れて本文**。

通知 ID は会話ごとに固定してあるので、**同じアプリなら2つ目が1つ目を置き換えます。**
置き換わらなかったのは、Android から見て**完全に別のアプリ**だからです。
We2 に debug 版が入っていなかったのが、そのまま答えでした。
