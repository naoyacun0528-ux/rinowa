# Lowan 0.20.3 — 静かに壊れる場所を1つ塞ぎました

0.20.2（規則の監査）を実機で確認する途中で見つけたものです。**規則の変更ではなく、
アプリ側の1か所**。

## 一覧の更新が、失敗しても誰にも分からなかった

メッセージを送ると、書き込みは2つ起きます。

```kotlin
created.set(payload).await()   // メッセージ本体 — 待つ
db.collection(...).set(...)     // 一覧の1行 — 待たない、結果も見ない
```

一覧の1行は送信の完了条件ではないので、**待たないのは正しい**設計です。終わった送信を
一覧の書き込み待ちで遅らせる理由がありません。

問題は**結果を捨てていた**ことでした。規則に弾かれても例外は出ず、ログにも残りません。
症状は「**メッセージは送れたのに、一覧だけ古いまま**」という静かな形になります。

まさに 0.20.2 で `lastMessage` に検査を足したとき、**それが効いているかを確かめる手段が
ここに無かった**。実機で目視するしかありませんでした。

**待たないまま、失敗だけ記録する**ようにしました。

```kotlin
db.collection(...).set(..., SetOptions.merge())
    .addOnFailureListener {
        android.util.Log.w("Lowan/messages", "last-message update failed", it)
    }
```

次に規則を変えたときは、ログに出ます。

### 同じ種類のものが他に無いか

このプロジェクトには「握り潰しには `swallow-ok:` と理由を書く」という規律があり、
`SwallowedErrorTest` が検査しています。ここは `runCatching` を使っていないので**検査に
掛かりませんでした**が、結果を捨てているという意味では同じです。

検査を「`runCatching` の握り潰し」から「結果を見ない非同期呼び出し」へ広げるかは、
別の判断として残します。広げると誤検知が増えるので、いまは1件を直すに留めます。

## 0.20.2 の確認結果（記録）

規則は配備済みで、実機で確認できました。

- メッセージが送れる
- **一覧のプレビューと時刻が更新される**
- 一覧には**本文**が出るが、**サーバーに入っているのは「🔒 メッセージ」**。
  `ChatListViewModel.previewFor` が端末で最新の1通を復号し直して差し替えている。
  **サーバーには本文が無いまま、画面には出る**

- コンパイル：エラー0・警告0、単体テスト70件すべて通過
- 規則のテスト：89件すべて通過（0.20.2 から変更なし）
- **実機未検証**（このログが出るのは規則に弾かれたときだけなので、
  普通に使っている限り何も出ないのが正しい）

## 2026-08-29 の追記

実機（Pixel 10 / arrows We2）で確かめた分。

### 直った不具合

**端末IDが入れ替わって、暗号がまるごと開かなくなっていた。**

アプリの名前を Echo → Rinowa に変えたとき、設定ファイルの移行を `CryptoEngine`
だけ書き忘れていた。端末IDが失われて新しく作られ、鍵の保管庫だけが古いIDのまま
残り、保管庫が開かなくなっていた。症状は「会話が全部まだ開けません」「安全画面が空」
「写真を押しても何も起きない」。

移行を足し、食い違ったときに保管庫のほうを信じて直す自己修復も入れた。
**新規の利用者は踏まない。** 改名をまたいだ端末だけで、それも次の起動で直る。

詳細は `docs/INCIDENT_2026-08-29_CRYPTO_DEVICE_ID.md`。

**Android 7 で着信が落ちる経路があった。** minSdk を 24 → 26 に上げた。
`NotificationChannel`（API 26以上）をバージョン確認なしで呼んでいて、
同種のものが27箇所あった。切ったのは2016年8月以前の端末。

**かけてすぐ切ると、通話が終わらないまま残っていた。** WebRtcSession が
`suspendCoroutine` を使っていて取り消しを見ていなかった。

**フィードバック画面から戻ると、会話一覧まで戻っていた。** 戻り先の表に
行が無く、既定に落ちていた。

### 速くなったところ

一覧が会話の数だけサーバーへ往復していた。通知のための `Source.SERVER` を
一覧が借りていたのが原因。分けて、待ちも直列から並列にした。

| | 一覧に中身が出るまで |
|---|---|
| Pixel 10 | **700 ms** |
| arrows We2 | **400 ms** |

どちらも出た時点で完成していて、待ちが残っていない。**圏外でも中身が出る。**

### 検査を足した

- `lint` を CI に入れた（入っていなかった）。エラーは 30 → 0
- 設定ファイルの改名漏れを見つける試験。今回の不具合そのものを機械が拾う
