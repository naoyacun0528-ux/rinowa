## ビデオ通話

会話画面の右上に**ボタンが2つ**になりました。

| | |
|---|---|
| **カメラのマーク** | ビデオ通話 |
| **受話器のマーク** | 音声通話 |

- 相手が画面全体、**自分は右上の小さい枠**
- **自分の映像は左右反転**します。反転しないと「他人から見た自分の顔」になり、
  鏡で見慣れた顔と違うので違和感が出ます
- **カメラ切／切替（前後）／ミュート／終了**
- ビデオ通話は**最初からスピーカー**です。耳に当てて見る人はいないので

### 着信で「どちらの通話か」が分かります

**応答した瞬間にカメラが点くかどうかは、押す前に分かるべきです。**

着信画面と通知に **「ビデオ通話」/「音声通話」** と出ます。
ビデオ通話に応答するときだけ、カメラの許可も同時に聞きます
（マイクの後にもう1つダイアログが出ると、鳴っている間に取り逃がすので1回にまとめました）。

### カメラが開けなくても通話は続きます

カメラが使えない端末や、許可が下りなかった場合、**音声通話として続行**します。
話したい2人は、カメラが無くても話したいので。

## コーデックの話（「その端末の最高の圧縮で」の件）

**まだ強制していません。実際に何が使えるかを集めている段階です。**

ハードウェア符号化できるコーデックを取得するようにしました（`supportedVideoCodecs()`）。
今は **WebRTC の既定の交渉に任せています**。理由は前に書いた通りで、

- **両方の端末が持っているものしか使えない**
- **ハードウェアで符号化できないと意味がない**（ソフトウェアで AV1 を回すと発熱と電池で破綻）

どちらも**端末に聞くまで分かりません**。まず2台が何を持っているかを見てから決めます。

そして正直なところ、**画質を決めるのは主に解像度とビットレートの適応**であって
コーデックの世代ではありません。720p/30fps を上限にし、
回線が細ければ WebRTC が自動的に落とします。

## 前回の続き — 中継について

**`relay 0` の原因は私でした。** 設定していた `openrelay.metered.ca` は
**DNS で解決すらできません**（サービス消滅）。ホテルの遮断ではありませんでした。
サーバー側から外したので、アプリは正しく「中継なし」と表示します。

**認証情報なしで使える公開 TURN は、現在ありません。**

ビデオ通話は音声より帯域を使うので、**中継が要る回線ではさらに厳しくなります**。
ただし**同じ Wi-Fi、違う Wi-Fi 同士なら中継なしで動く見込み**は音声と同じです。

## 試す順番

1. **同じ Wi-Fi でビデオ通話** — まず映像が出るかを確認
2. 出たら**違う回線同士**で
3. 失敗したら通話画面の文言をそのまま貼ってください

映像が出ない場合、**黒い画面ではなく「映像を待っています…」と出る**ようにしてあります。
黒画面は「壊れている」と「まだ来ていない」の区別がつかないので。
