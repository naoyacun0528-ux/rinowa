# Lowan 0.20.0 — LOWAN SIGIL と、安全性の確認

## 封の仕組みに名前が付きました

**LOWAN SIGIL**（シジル）。本文・写真・動画・通話・バックアップを、送る端末と
受け取る端末の間だけで読める形にする一式の呼び名です。

sigil は「封印の紋章」で、**1つ1つに刻むもの**を意味します。Lowan はメッセージ
1通ごとに封をする（`MessageEnvelope`）ので、盾や結界のような「境界の内側は安全」の
比喩は採りませんでした。**E2EE に安全地帯はありません。** サーバーの中も外も同じく
信用しない、というのがこの仕組みの前提です。

**適用範囲の正本は [`docs/LOWAN_SIGIL.md`](../../docs/LOWAN_SIGIL.md)。**
何が守られていて何が守られていないかは、あの表がすべてです。

```
LOWAN SIGIL   封の仕組み
LOWAN DIRECT  サーバーを経由しない経路
RINOWA        独自バイナリ形式
```

## 安全性の確認（V-1 / V-2）

会話の**名前か顔をタップ**すると開きます。

- **この端末の指紋**（Ed25519 の公開鍵）
- **相手の端末の一覧**と、それぞれの指紋・初めて見た日

指紋は4文字ずつ区切って**等幅**で出します。43文字を一息で照合するのは無理で、
`l` と `1`、`O` と `0` が同じ形だと読み合わせが成立しないためです。

### なぜ必要だったか

**SIGIL に残っていた最後の穴でした。** 公開鍵はサーバーが配っていて、検証する第三者は
いません。これは LINE も Signal も同じで、そこは変えられません。変えられるのは
「**確かめたい人が確かめられるか**」だけで、**そこだけ LINE に負けていました**。

LINE の技術白書にこうあります。

> There is no trusted third party who verifies public keys. Nevertheless, there is a way
> for users to verify the recipient.

これで並びました。

### 「確認済み」とは表示しません

押した記録を残す仕組み（V-5）がまだありません。済んだように見せると、検証機能そのものが
飾りになります。画面には**分からないことも書いてあります** — 番号が変わったときに知らせる
仕組みはまだ無いこと、誰と誰がいつ話したかはサーバーから見えること。

**SIGIL が守るのは中身で、関係ではありません。**

## 途中で1つ間違えました

端末の「初めて見た日」が **1月15日・3月8日**という無関係な日付になりました。
FFI の `firstTimeSeenTs` を秒だと決めつけて1000倍したためです。単位は資料に
書かれていませんでした。

**推測を残さず実機で確かめました。** そのまま使うと実際の登録日（昨日・8月20日）と
一致したので、ミリ秒です。コードにその経緯を書き残しました。

## 分かっていないこと

一覧に出た We2 の端末は **2台**（昨日 / 8月20日）でした。しかし We2 は**今日2回
データを消しており**、そのたびに新しい端末として登録されているはずです。
**今日の登録が出てきません。**

仮説は「`getUserDevices` が返すのは端末情報の問い合わせを済ませたものだけで、
Pixel の最後の問い合わせが今日の消去より前だった」ですが、**確かめていません。**

皮肉ですが、**この画面が無ければこの疑問自体に気づけませんでした。** V-2 が
やるべき仕事はしています。次に追います。

## 確認したこと

- コンパイル：エラー0・警告0、単体テスト70件すべて通過
- 実機（Pixel 10、release）で会話名をタップ → 指紋が出る
- 自分の端末 ID（KXTCPHYMEC）が Direct Lab の E2EE 検証で出るものと一致
- 端末が2台以上あるときの注意書きが出る
