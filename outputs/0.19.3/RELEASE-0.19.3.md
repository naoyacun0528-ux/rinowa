# Lowan 0.19.3

**0.19.0 で私が入れた退行を1つ直します。** 実機の消去・復元の検証で出ました。

## 1. 移行前からある端末が、誰からも到達できなくなっていた（退行）

0.19.0 でワンタイム鍵の置き場所を `users/{uid}/oneTimeKeys/` から
`users/{uid}/cryptoDevices/{deviceId}/oneTimeKeys/` へ移しました。**移した先へ公開し直す
仕掛けを入れ忘れていました。**

エンジンは「サーバーに鍵が何個あるか」を自分では知りません。教えられたときだけ知ります。
そして `receiveSyncChanges` の `keyCounts` に**ずっと空の map を渡していました**。

```kotlin
keyCounts = emptyMap(),
```

そのためエンジンは、最後に公開したときの記憶（＝旧パスに数十個ある）を持ち続け、新しい
場所へ公開し直しません。結果:

- **その端末は送れる。しかし誰もセッションを張れない。** 鍵を1つも取れないので。
- 相手には「まだ開けません」だけが出る。**どこにもエラーが出ない。**
- 新規導入・データ消去後の端末は無事（最初から新しい場所に公開するため）

実機ではこう見えました。データを消した We2 から Pixel へ送ると、Pixel 側は永久に
`MissingRoomKey`。送った側のログは `shareRoomKey ... devices=2 requests=1` で、
成功したように見えます。Pixel の受信箱は `mailbox docs=0` のまま。

### 直し方

在庫の実数を数えてエンジンに渡します。受信箱が空の回も渡します——**空だからと早く
帰っていると、鍵を使い切った端末は永久に気づけません**。誰もセッションを張れないので
to-device も届かず、受信箱は空のまま。「何も来ていない」と「もう誰も来られない」が
同じ見た目になります。

数えるのは5分に1回まで。起動直後は必ず1回数えるので、移行後の端末はそこで気づきます。

### 効いていることの確認

同じ手順を2回、修正の前と後で実行しました。**どちらも「消したばかりの端末から先に
送る」**で、相手（移行前からある Pixel）が読めるかを見ています。

| | 修正前 0.19.2 | 修正後 0.19.3 |
|---|---|---|
| 送信側が出した鍵配布の要求 | `requests=1` | **`requests=2`** |
| to-device の書き込み確認 | 記録なし | **`readback present=true` ×2** |
| 受信側の受信箱 | `mailbox docs=0` | 届いて復号 |
| 画面 | まだ開けません | **本文が読める** |

修正前は、移行前からある端末の鍵を1つも取れないので要求が立ちませんでした。修正後は
その端末が新しい場所へ公開し直しているので、取れます。

原因の分析自体は実機に依らず成立します（`keyCounts = emptyMap()` はコードにそう
書いてあり、エンジンが在庫を知る経路が他にありません）。

## 2. 復元しても、開いている画面が変わらなかった

**復元は成功していました。** 押した直後の画面が変わらないだけでした。

バックアップの復元は端末内の対応表を書き足すだけで、Firestore は何も動きません。
スレッドは Firestore の更新で開き直すので、復元しても前の結果を映したままになります。
押した人には「復元できなかった」に見えます——実際には復元できていて、次にアプリを
開き直せば読めます。

復元のたびに増える数を持たせ、開いているスレッドがそれを見て開き直すようにしました。

実機では、消去直後は全部「まだ開けません」だったスレッドが、復元後（アプリ再起動を
挟んで）「不在着信 14:37」「通話時間 0:58 / 1:42」まで読めることを確認済みです。

## 3. 直していないもの

- **消去前の端末の登録が残ります。** 端末を消すと新しい id で登録され、古い登録は
  残ったままです（実機のログで `devices=2`）。送信側は死んだ端末にも配ろうとします。
  害は「無駄な1回」ですが、増え続けるので、いずれ掃除が要ります。
- **鍵が届かなかった時期のメッセージは、そのまま開けません。** 今日の 15:20 の2通と、
  0.19.1 より前の通話記録がそれに当たります。鍵を配り直す経路がありません。

## 確認したこと

- コンパイル：エラー0・警告0、単体テスト70件すべて通過
- 実機（Pixel 10 / arrows We2）
  - データ消去 → 再ログイン → 一覧が復帰、履歴は全部「まだ開けません」（E2EE が正しい）
  - **消したばかりの端末から先に送って、相手が復号できる**（上の対比表）
  - 逆方向も復号
  - 復元した内容がスレッドに出る
  - 通知の許可を求める画面が、消去後の初回に1度だけ出る
