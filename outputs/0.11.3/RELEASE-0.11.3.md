## 「違う Wi-Fi 同士」はどうなのか

**同一ネットワークの次に有望なケースです。** ただし推測で答えたくないので、
**その場で判定できる機能**を入れました。

### 理屈

繋がるかどうかを決めるのは **Wi-Fi かモバイルか**ではなく、
**そのルーターの NAT の性質**です。

- **家庭用ルーターの多くは「素直な NAT」**（外向きポートを接続先ごとに変えない）。
  この場合 STUN だけで繋がります。**違う家の Wi-Fi 同士は、たいていこれです**
- **対称 NAT**（接続先ごとにポートを変える）だと STUN が役に立たず、中継が要ります。
  学校・会社・公衆 Wi-Fi に多い
- **モバイル回線**は CGNAT で、対称 NAT になりやすい

さらに日本の光回線は **IPv6 が来ていることが多く、IPv6 には NAT がありません**。
両側に IPv6 があれば、**中継どころか STUN すら要らずに直接繋がることがあります**。

### 順位（あくまで一般論。だから測ります）

| 組み合わせ | 見込み |
|---|---|
| 同じ Wi-Fi | ほぼ確実 |
| **違う家の Wi-Fi 同士** | **高い**（IPv6 があればさらに） |
| 家の Wi-Fi ↔ モバイル | 中 |
| モバイル ↔ モバイル | 低い。中継がほぼ必須 |
| 学校・公衆 Wi-Fi が絡む | 低い |

## 相手が要らない回線チェックを入れました

> **Direct Lab → 「通話できる回線か確認」→ 「確認」**

**1台で完結します。** 通話が繋がるかを決める条件のほとんどは
**それぞれの回線の性質**なので、片方ずつ別の時間に調べて比べられます。

最大12秒で、こう出ます。

```
この回線の判定
  良好。IPv6 もあるので直接繋がる可能性が高い
  host 4 / srflx 2 / relay 2
  IPv6 あり
  外から見えるポート 54321（一定 = 素直なNAT）
```

### 判定の意味

| 出るもの | 意味 |
|---|---|
| `host` のみ | **STUN にすら届いていない。** その回線が UDP を塞いでいる |
| `+ srflx` | STUN 成功。**相手も素直なら繋がる** |
| `+ relay` | 中継も使える。**相手が何であれ繋がる** |
| ポートが**一定** | **素直な NAT。** これがいちばん重要 |
| ポートが**バラバラ** | **対称 NAT。** 相手も対称だと中継が必須 |

**ポートが一定かバラバラか**が核心です。異なる2つの STUN サーバーに聞いて、
返ってきた外部ポートが同じなら素直な NAT、違えば対称 NAT。
**これは1台で分かります。**

**IP アドレスは出しません。** 種別とポート番号だけなので、そのまま貼れます。

## やってほしいこと

1. **家の Wi-Fi で「確認」** → 結果を控える
2. **モバイル回線に切り替えて「確認」**（Wi-Fi を切る）→ 結果を控える
3. 可能なら**別の Wi-Fi でも**

**この2〜3回で、TURN が要るかどうかが分かります。**
両方「ポート一定」なら中継は要りません。片方でも「バラバラ」なら、
相手側次第で中継が必要になります。
