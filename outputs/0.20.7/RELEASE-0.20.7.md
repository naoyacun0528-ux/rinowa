# Rinowa 0.20.7

2026-09-05。**実機で確かめてほしいのはこの版。** 0.20.5 と 0.20.6 は端末に
入れていない（作ったあとに直すものが見つかったので、番号を上げ直した）。

0.20.6 までの14件の修正に加えて、一覧の速さと触覚の設定が入っている。

---

## 一覧が軽くなった

一覧の1行（名前の下に出る、最後に言われたこと）は、**画面に戻るたびに作り直して
いた。** 通信はしていないが、**会話の数だけ暗号を開いていた。** 100人いれば
100回。しかも一覧は、会話から戻るたびに描き直される。

開いた1行をこの端末に置くようにした。次からは**取り出すだけ**で、暗号の仕事が
無くなる。

**古い1行は出さない。** 新しいものが来ていれば読み直す。速さのために「最後に
言われたこと」が古くなるのは割に合わない——そこが古いと「まだ返事が来ていない」
ように見える。

置き場は端末の中だけ。**サインアウトと退会で消える**（残すと、次にこの端末を
使う人に前の人の会話が見えてしまう）。クラウドのバックアップにも載せない。

---

## 振動の強さを選べるようになった

アカウント画面に **なし／弱／標準／強** を出した。押すとその強さで1回鳴るので、
違いをその場で確かめられる。

**設定そのものは前からあった。** ただし触れる場所が開発用の画面だけで、しかも
**変えても保存されていなかった**（次の起動で元に戻っていた）。両方直した。

### 実験室に「立ち上がり」を足した

arrows We2 で触覚がほとんど感じられない件は、**まだ直っていない。**

原因までは分かっている。強さの段は API とハードウェアをちゃんと見て決めているが、
問い合わせて分かるのは「その命令を受け付けるか」であって「**強く出るか**」では
ない。「このモーターは弱い」を答える API は Android に無い。そして段を落としても
弱くなるだけで、強くする道が用意されていない。

もう一つ疑っているのが**長さ**で、いまの触覚は最短 8ms。安いモーターは回り切る
までに 20〜30ms かかるので、**強さをいくら上げても届いていない可能性がある。**

そこで実験室（一覧の隠し操作で開く）に **8 / 12 / 16 / 24 / 32 / 48 / 64ms** を
順に押せる段を足した。**上から押していって、最初にはっきり分かるところが
この端末の下限。** 強さのつまみは掛けていないので、「短くて出ない」のか「弱くて
出ない」のかが分かれる。

**その数字が分かれば直せる。** 当てずっぽうで伸ばすより、押してもらったほうが早い。

## 分かっていて直していないこと

- **arrows We2 の触覚**（上記。下限の数字を測ってから）
- 写真のディスク上の上限は繋いでいない。**あれは利用者の写真を消す処理**なので、
  繋ぐかどうかは持ち主が決めること
- 動画は毎回落とし直している。壊れはしないが通信量が倍
- iOS は画面だけで、中身（通信・暗号・通話）が無い
