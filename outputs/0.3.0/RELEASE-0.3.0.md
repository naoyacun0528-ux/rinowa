# Echo 0.3.0

2026-08-15 / Prototype 0 / Android only

**ガラス調 UI の第一歩。** 屈折を使わない方式で、押すと膨らみ、触れた場所が光ります。

---

## 触ってわかる変更

### メッセージ一覧がカードになった

各会話が角丸のガラス面になり、背景から浮きます。
**押すとカードが少し膨らみ、指の位置から光が広がります。**

縮むのではなく**膨らむ**のは意図的です。縮むと「押しのけられた」ように読め、
膨らむと「応えた」ように読めます。

### コンポーザーのボタンがガラスになった

`+` とスタンプのボタンが円形のガラス面になりました。同じく押すと膨らんで光ります。
送信ボタンにも縁のハイライトと影を入れています。

### 背景を少し深くした

`#FBF9F7` → `#F2EDE7`。**ガラスが浮くには、ページがガラスより暗い必要がある**ためです。

副作用として受信バブルが背景とほぼ同色になり消えかけたので、
**受信バブルを白**に変えました。カードと同じ「紙の上に浮く面」の仲間になります。

---

## 屈折を使わない理由

「ガラス」といえば普通は屈折ですが、これには API 33、AGSL シェーダー、そして決定的に
**背後に屈折させる価値のあるもの**が要ります。

このアプリの背景はほぼ一様な暖かい紙です。**一様な面を屈折させてもクリーム色にしかなりません。**
高いコストを払って何も見えない、という結果になります。

明るい背景でガラスに見えるのは、もっと単純で安いものです。

- 上端が光を拾う縁
- 完全には平らでない面
- ページから持ち上げる柔らかい影
- そして最も効くのが、**触れられたことに答える表面**

シェーダーが不要なので **minSdk 24 から全端末で同じ見た目**になり、
GPU コストは屈折の数分の一で済みます。

## 性能

同じ操作（46件のスレッドを約8秒スクロール）での比較です。

| 指標 | 0.2.0 | 0.2.1 | **0.3.0（ガラス）** |
|---|---|---|---|
| Janky frames | 1.67% | 2.55% | **0.74%** |
| 50th percentile | 6 ms | 6 ms | **6 ms** |
| 90th percentile | 11 ms | 12 ms | **10 ms** |
| 95th percentile | 15 ms | 16 ms | **12 ms** |
| 99th percentile | 31 ms | 32 ms | **17 ms** |
| GPU 99th percentile | — | 2 ms | **5 ms** |

**悪化していません。3回の測定で最良の結果でした。**

GPU は 2ms → 5ms へ増えています（ガラスが消費するのはここ）。
それでも 8.33ms の予算内に収まっています。

> 撤退条件は「測定値が悪化したら戻す」でした。悪化しなかったので残します。
> ただし面を増やせば GPU は増えます。**広げるたびに測り直します。**

## Haptic Lab の表示を修正

「既定の Tier は T4 なのに、トークンは T3 と出る」のが分かりにくかったので、
**制限中であることを明示**するようにしました。

```
Send        T3 制限     ← 端末は T4 対応だが、意図的に下げている
Error       T4          ← 端末の最上位をそのまま使う
```

端末の能力（カード上部）と、そのトークンで実際に使う Tier（バッジ）は別物です。
短いトークンを T3 に制限している理由は Envelope の最短 20ms 制約によるものです。
