# Lowan 0.15.5

## 握り潰しを、意志ではなく機械で止めます

「気をつけます」は何度も言って何度も破りました。**約束は機能しませんでした。**

`app/src/test/.../SwallowedErrorTest.kt` を追加しました。
ソースを走査して、**例外を捨てているのに報告していない箇所があるとビルドが落ちます。**

```
runCatching { ... }.getOrNull()        ← ビルドが落ちる
runCatching { ... }.getOrDefault(x)    ← ビルドが落ちる

runCatching { ... }.onFailure { 報告 }.getOrNull()   ← 通る
// swallow-ok: 報告する情報が無い理由                  ← 通る
```

**逃げ道には理由を書かせます。** 一度だけ、文章で答えさせる。次の人が反論できる形で。

### 最初に走らせたら 81 件出ました

「何回か」ではありませんでした。**81 件**です。

検出器自体に2つバグがあり、それも直しました
（`return@runCatching` を拾う／チェーンの外まで見る）。
**誤検出する検査は、無視する習慣を作るだけ**なので。

修正後に実件数 **37 件**。全部潰して **0 件**です。内訳:

- **報告するようにしたもの** — 暗号の全経路、FCM トークン取得、通話の取得、
  着信音、カメラ起動、写真の保存と共有、既読数、設定の同期
- **`swallow-ok:` を付けたもの** — 権限の存在確認（例外が答えそのもの）、
  キャッシュの復号失敗、ソケットの close（例外が停止信号）、投票数の表示

暗号層の失敗は `CryptoProblems` に記録され、**Direct Lab から読めます。**
本文・平文・鍵は**絶対に入れません**。

### 効くことを確かめました

わざと `runCatching { }.getOrNull()` を1行足したら、**ビルドが落ちて行番号が出ました。**
そのあと戻しています。

## 計測について、前回の推論を撤回します

**同じ端末・同じ暗号コードで測り直したら、数字が半分になりました。**

| Pixel 10 | 前回 | 今回 |
|---|---|---|
| 定常 encrypt | 12,478 us | **5,967 us** |
| └ 暗号化（Megolm） | 5,521 us | **2,190 us** |

前回「準備が2機種でほぼ同じ（6,139 と 6,161）だから CPU 依存ではない」と書きました。
**その一致は偶然でした。** 同じ端末で 6,139 → 3,201 に動きます。

新しい数字だけ見ると Pixel 2,190 対 We2 7,288 で **3.3倍差**、
Rinowa の CPU 差（3.5倍）に近く、**逆の結論すら支持します。**

**どちらとも言いません。** 分かったのは1つだけです。

> **この計測は1回では足りません。**
> 同じ端末で倍動く量を、機種間比較や原因の推定に使ってはいけない。

**採用の判定は変わりません**（定常 6〜15 ms/通、Firestore の往復に埋まる）。
変わったのは「なぜその値か説明できる」と思っていた部分で、**説明できていませんでした。**
