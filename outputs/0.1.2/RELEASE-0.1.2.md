# Echo 0.1.2

2026-08-15 / Prototype 0 / Android only

配布用の署名鍵を作り、**署名済みの release ビルドを初めて出力しました。**
アプリの機能は 0.1.1 から変わっていません。

---

## 何が変わったか

### 署名鍵を作成した

Android は署名鍵で「同じアプリである」ことを判定します。
これまで出していた debug ビルドは開発用の自動生成鍵で署名されており、
配布には使えませんでした。

専用の鍵を作成しました。

- RSA 4096bit / SHA384withRSA
- 有効期間 10000日（約27年）
- 鍵ファイルは**リポジトリの外**（`C:\dev\echo-keys\`）に配置
- パスワードは生成時のランダム値で、`android/keystore.properties` に記録（git 管理外）

**この鍵を失うと、配ったアプリへ二度とアップデートを届けられません。**
バックアップの手順と、失った場合に何が起きるかは [docs/SIGNING.md](../../docs/SIGNING.md) に書いてあります。
**必ず読んで、バックアップを取ってください。**

### release ビルドが 1/10 以下になった

R8 による不要コードの削除とリソース圧縮が効いています。

| ビルド | サイズ |
|---|---|
| debug | 11.59 MB |
| **release** | **1.23 MB** |

友人に配る場合は release のほうを使ってください。

### 出力スクリプトが自分の出力を検査するようになった

ソース zip を作った後、**中身に秘密ファイル（署名パスワード等）が入っていないか走査し、
見つかったら zip を破棄して停止**します。

除外リストは「更新し忘れる」種類の仕組みなので、完成物そのものを検査する形にしました。
署名パスワードは一度共有すると取り消せないため、報告ではなく破棄にしてあります。

（この安全装置は、実際に一度 zip へ `keystore.properties` が混入したのを検知して追加したものです。
その zip は外部へ出る前に削除済みで、鍵の再作成は不要と判断しました。）

## 成果物

| ファイル | 用途 |
|---|---|
| `echo-0.1.2-release.apk` | **配布用。** 専用の鍵で署名済み、1.23 MB |
| `echo-0.1.2-debug.apk` | 開発用。`jp.echo.android.debug` として入る |
| `echo-0.1.2-source.zip` | ソース一式（秘密ファイルなしを検査済み） |

release と debug は applicationId が違うため、**同じ端末に両方入れられます。**

---

## 入れ方

```bash
adb install -r echo-0.1.2-release.apk
```

すでに debug 版が入っていても衝突しません。別アプリとして並びます。

**注意:** 一度 release 版を入れた端末に、将来別の鍵で署名した APK は入りません。
その場合はアンインストールが必要になり、データが消えます。
これが鍵を失ってはいけない理由です。

---

## 署名の確認

この APK が本当にこの鍵で署名されているかは、次で確認できます。

```bash
apksigner verify --print-certs --min-sdk-version 24 echo-0.1.2-release.apk
```

期待される値:

```
SHA-256  53:15:50:1D:D0:83:20:A3:5E:A8:41:B4:EE:48:B7:C5:CB:56:27:E1:BF:FA:67:D4:49:35:91:AD:C4:38:5F:F9
```
