# Echo 0.12.5

0.12.4 で出した3つのうち2つが実際には動いていませんでした。原因と直し方を書きます。

## 斜線もぼかしも見えなかった件 — 原因を取り違えていました

0.12.4 では、生きている `VideoSurface` の**上に**覆いと斜線と文字を描いていました。
それが一切見えなかったのは、描き方が弱かったからではありません。

`SurfaceViewRenderer` は `SurfaceView` です。映像はウィンドウの**外側**でシステムが
合成し、ビューは自分の矩形をウィンドウ上でクリアして、その映像を透かせます。
**同じ矩形に Compose が描いたものは、一緒にクリアされます。**
覆いは毎フレーム描かれては消されていました。

**これは以前の「映像が重なると黒くなる」と同じ仕組みで、そこが手掛かりだったはずです。**
`setZOrderMediaOverlay` でその件を直したとき、同じ結論に到達しているべきでした。

### 直し方

覆うのをやめました。**レンダラをレイアウトから外し、その場所に最後のフレームを描きます。**

映像が届いている間に `EglRenderer.FrameListener` でフレームを1枚ビットマップとして
取り出しておきます（3秒ごと、約1/12サイズ）。カメラが切れたら、レンダラを外して
そのビットマップを普通の Compose の画像として描きます。**外部合成が関わらなくなるので、
覆いも斜線も文字も、ただの重ね描きになります。**

**ぼかしは本物になりました。** 1/12 に縮めた絵を画面いっぱいに拡大するので、
再サンプリングそのものがぼかしです。**API 31 も RenderEffect も要りません。**
`Modifier.blur` は有る環境では追加で掛けますが、効果はそれに依存していません。

斜線は暗い線の上に明るい線を重ねた2本にしました。明るいフレームの上では
白1本は消えるからです。

## 通知から終了しても相手が反応しなかった件

**通知の PendingIntent が `CLEAR_TOP` で Activity を作り直していました。**
MainActivity は `standard` だったので、通知から戻ると再生成が起きます。

コントローラは `rememberCoroutineScope()` を使っていました。
つまり **Firestore に `Ended` を書くコルーチンが、起動される前にスコープごと
キャンセルされていました。** こちら側は切れて、相手には何も届きません。

2か所直しました。

1. `MainActivity` を `singleTop` に。通知は Activity を作り直さず `onNewIntent` に来ます。
2. **通話を Application のスコープに移しました。** 通話の終了は画面の仕事ではありません。
   Activity が作り直されても、`Ended` の書き込みは走りきります。

1 だけでも今回の症状は消えますが、2 が無いと「Activity が作り直される別の経路」で
同じことが起きます。

## PiP に自分の顔を載せました

左上、全画面と同じ角です。小窓は数センチしかないので、相手が読める大きさを
残す比率にしてあります。重なる2枚は `overlay` 指定です（無いと重なりが黒くなる）。

## ミュートとカメラのボタン

**全画面**：一度タップすると出て、しばらくで消えます。LINE と同じです。
最初は出た状態で始まります（ミュートの手段が無いまま通話に入るほうが不安なので）。
エラー表示だけは消えません。読んで消すまで残ります。

**小窓**：システムの操作列に **マイク / カメラ / 終了** を出しました。
自分で描いたボタンではありません。**PiP の窓はタップを受け取らない**
（触ると「窓を広げる」の意味になる）ので、自分で描いたボタンは押せません。
システムが `RemoteAction` から描き、押すとブロードキャストが飛びます。
アプリを前面に戻さないのは、ミュートのために戻ってしまっては小窓にした意味が
無いからです。

アイコンは**今の状態**を出します（ミュート中ならマイクに斜線）。
押すたびに列を作り直しているので、操作した結果が同じ場所に出ます。

## 実機確認はまだです

3機種いずれでも触っていません。特に PiP の操作列は端末の実装差が出やすい部分です。
