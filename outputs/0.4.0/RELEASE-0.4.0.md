# Echo 0.4.0

2026-08-15 / Prototype 0 / Android only

**上下のバーが本物のすりガラスになりました。** メッセージがバーの後ろを流れ、そこがぼけます。

---

## 変更点

### メッセージがバーの下に潜るようになった

これまではスレッドが上下のバーに**挟まれた領域**をスクロールしていました。
バーの後ろには何も無かったので、すりガラスにしても意味がありませんでした。

スレッドを画面全体に広げ、バーをその上に重ねる構造へ変えました。
上下の端は `contentPadding` で確保しているので、最初と最後のメッセージは隠れません。

### バーがすりガラスになった

背後のスレッドを取り込み、ぼかして、その上に薄い色を重ねています。

**この2箇所だけです。** 読むための面（メッセージ本体）は不透明のままです。
バーは名前とボタンを置く場所であり、読むためのものではない。だから透けてよい。

### 下のバーが透けていなかった不具合も修正

コンポーザーが自分で不透明な背景を持っていて、すりガラスの上に板を載せていました。

## 性能 — 正直な数字

**これは悪化しています。**

| 指標 | 0.3.2（バーなし） | 0.4.0 途中版 | **0.4.0 最終** |
|---|---|---|---|
| Janky frames | **0.74%** | 4.14% | 3.29% |
| 50th percentile | **6 ms** | 10 ms | **7 ms** |
| 90th percentile | **10 ms** | 15 ms | 12 ms |
| GPU 50th | 1 ms | 3 ms | 1 ms |

### 分かったこと: 高いのは「ぼかし」ではない

ぼかし半径を 26dp → 14dp に下げたところ、**GPU は 9ms → 4ms に半減したのに、
総フレーム時間はほとんど変わりませんでした。**

コストの正体は **リストを一度オフスクリーンに描き写す処理**です。
背後を取り込む方式である以上、ぼかしを弱めても消えません。

### 対策: 動いている間は取り込まない

スクロール中は描き写しをやめ、**バーは薄い色だけ**にしました。
止まると取り込みが再開してぼけます。

バーは**どちらの状態でも半透明**なので、切り替わるのは
「透明／不透明」ではなく「くっきり／ぼけ」です。変化は静かなはずです。

これで中央値は 7ms に戻り、**120Hz の予算 8.33ms 内**に収まりました。

### それでも残る差

Janky frames は **0.74% → 3.29%**。ベースラインには戻っていません。

私が先に決めた撤退条件は「測定値が悪化したら戻す」でした。
**厳密にはこれは撤退条件に該当します。**

一方で中央値は予算内であり、この機能は明確に要望されたものです。
**残すかどうかは判断が要ります。** 数字は上のとおりです。
