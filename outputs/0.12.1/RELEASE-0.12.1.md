
**2台とも更新してください。**

---

## 何が起きていたか

応答を押すとチャット画面が出て終わり、発信側は永久に呼び出し中。**私のバグです。**

原因は3つ重なっていました。

### 1. 着信を監視するクエリが Firestore で失敗していた

```
whereEqualTo("state", "ringing").orderBy("startedAt")
```

この形は **複合インデックスが必要**で、無い場合 Firestore は「該当なし」を返すのではなく
**リスナーごとエラーで落とします**。インデックスを作っていませんでした。

### 2. そのエラーを私が握り潰していた

```kotlin
if (error != null) return@addSnapshotListener   // ← これ
```

**「インデックスが無くて壊れている」と「誰もかけてきていない」が、
アプリからは完全に同じに見えていました。** 一番たちの悪い形の失敗です。

### 3. 応答の処理が、その壊れたリスナーに依存していた

通知から応答すると、まだ何も起動していないプロセスで押されます。
そこから「リスナーが着信を教えてくれるのを待つ」設計だったので、**永遠に待ちました。**

---

## 直したこと

**インデックスを要らなくしました。** 並べ替えだけにして、状態の判定は端末側でやります。
単一フィールドのインデックスは自動で作られるので、**デプロイ手順の抜けで壊れる余地がなくなりました。**

**応答は通話 ID で直接取りに行きます。** 通知が持っている ID でその通話を1件読むだけなので、
リスナーの状態に関係なく成立します。

**エラーを表示します。** 着信監視が失敗したら画面に出ます。

**発信側にタイムアウトを入れました。** 35秒で「応答がありませんでした」。
鳴っていない相手を無限に呼び続けるのは、通話としては壊れています。
