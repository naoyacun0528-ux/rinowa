# Lowan 0.14.0 — 通話がスレッドに残るようになりました

LINE と同じ見え方です。かけた側は右、受けた側は左に出ます。

| 状況 | かけた側 | 受けた側 |
|---|---|---|
| 通話した | 通話時間 3:12 | 通話時間 3:12 |
| 出なかった | 応答なし | **不在着信**（赤） |
| 拒否された | 相手が応答しませんでした | 通話を拒否しました |
| つながらなかった | つながりませんでした | つながりませんでした |

**タップするとかけ直します。** ビデオ通話の記録をタップすればビデオ通話になります。

## 記録は1件しか作りません

**発信した側だけが書きます。** 両方が書くと、1回の通話がスレッドに2回出ます。しかも
2つの記録は**通話時間が食い違います** — それぞれが自分の接続を測っているので。

同じ1件を、読む側によって違う文章にしています。「誰も出なかった」は、かけた人には
応答なし、受けた人には不在着信。**同じ事実を、2つの場所から言っているだけです。**

代償も書いておきます。**発信側のプロセスが、通話終了と書き込みの間に死ぬと、記録は
1件も残りません。** これは意図した失敗の仕方です。存在しない通話がスレッドに出るより、
出ないほうがましなので。

## 通話時間は「話した時間」です

**呼び出していた時間は入りません。** 相手が電話を探していた20秒を通話時間に足すと、
全部の記録が水増しされます。音声が流れ始めた瞬間から数えます。

途中でWi-Fiからモバイルに切り替わって再接続しても、時計は**測り直しません**。同じ会話なので。

## 権限ルールも足しました

`callSeconds` に **86,400秒（24時間）の上限**を置いています。上限が無いと
「1兆秒の通話」を書き込めてしまい、**記録が記録ではなく主張になります。**
種別と結果も列挙値に固定していて、ここから文字列を通すことはできません。

ルールテストは **38件 → 45件**。追加した7件は全部「書けないこと」の確認です。

## 直したもの

**ROADMAP が実態と食い違っていました。** グループ作成 UI とプロフィール編集を
「未着手」と書いていましたが、どちらも実装済みです（`NewGroupScreen.kt` /
`ProfileScreen.kt`）。実装済みのものを未着手と書いた状態で残すと、次に何を作るかの
判断を間違えるので直しました。
