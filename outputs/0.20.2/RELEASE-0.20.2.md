# Lowan 0.20.2 — 規則の監査（アプリの変更なし）

外部レビューは**会話の節**を見て P0 を1件出しました。**他の節は同じ検査を受けて
いませんでした。** 同じ目で残りを洗い、**3件を塞ぎました。**

アプリのコードは1行も変えていません。変えたのは `firestore.rules` だけです。

---

## 1. 一覧に出る「最後の1行」を、他人の名前で書けた（一番大きい）

会話の update は `lastMessage` を書き換え可能な項目に含めながら、**中身を一切
検査していませんでした。**

参加者なら誰でも、こう書けました。

```js
lastMessage: { preview: '今日は休みます', senderId: <相手のuid>, kind: 'text' }
```

会話を開けば本物のスレッドが出るので**本文は偽装できません**。しかし**一覧には、
送っていない文が相手の名前で並びます**。しかも暗号化したメッセージのプレビューは
本来「🔒 メッセージ」なので、**そこに平文が出ること自体が嘘**になります。

**送信者を自分に限りました。** 自分が送った1行だけを書けます。項目も4つに絞り、
プレビューは200文字までにしました。

## 2. 公開プロフィールに、項目の制限が無かった

`users/{uid}/public/{doc}` は写真の**大きさ**だけ見て、**項目**を見ていませんでした。
署名済みの誰もが、自分の公開文書を好きな形にできます。ここは**全利用者が読める**ので、
「誰でも読める置き場」として使える状態でした。

`bytes` と `updatedAt` だけに絞りました。

## 3. 写真の旧保管庫が、書き込みに開いたままだった

`media/` は保管庫を XServer へ移す前の遺物です。アプリは
`MediaRepository.fetchLegacy` から**読むだけ**（しかもハッシュを取り直して照合します）。
**書く経路はもうありません。**

一方で規則は「64文字の id なら誰でも 900KB 置ける」を許したままでした。
**正規の利用者が1人もいない書き込み口は、置き場所を提供しているだけです。** 閉じました。

---

## 塞がなかったもの（記録）

**自分のプロフィールに、他人の招待コードを書けます。**

ただしアプリは `inviteCode(profile.id)` で**自分のコードしか表示しません**。
他人を騙す経路が無く、**自己申告が狂うだけ**です。

塞ぐには「そのコードの台帳が自分を指しているか」を規則から読む必要があり、
**アカウント作成の順序に依存します**。実機で登録をやり直せない状態で触ると、
得るものより壊すもののほうが大きいと判断しました。

---

## 通っていたもの（4件）

同じ検査をかけて、**問題が無かった**ことを確認したものです。

- 他人のスタンプを消せない
- 他人の名前で投票できない
- 他人の to-device 受信箱を読めない
- すでに使われている招待コードを奪えない

## 確認したこと

規則のテストは **77件 → 89件**。すべて通過。

**禁止と許可を対で置きました。** 検査を足したせいで自分の1行も書けなくなっていたら、
送信そのものが止まります。

| 追加したテスト | |
| --- | --- |
| 他人の名前でプレビューを書けない | 拒否を確認 |
| **自分のプレビューは書ける** | **通ることを確認** |
| 余分な項目を混ぜられない | 拒否を確認 |
| プレビューの長さに上限がある | 拒否を確認 |
| **自分のプロフィール写真は書ける** | **通ることを確認** |

アプリ側の書き込み経路も全部たどりました。会話の作成は `lastMessage = null`（`create`
なので今回の検査の対象外）、送信は4項目で `senderId` は自分。**現行のアプリは壊れません。**

## 配備しました・確認できました（2026-08-26）

`firebase deploy --only firestore:rules --project echo-cfe37` → released。
**アプリの入れ替えは不要**でした（変えたのは規則だけ）。

実機（Pixel 10、0.20.1 のまま）で1通送って確認。

- メッセージが普通に送れる
- **一覧のプレビューと時刻が更新される** ← ここが本命
- 一覧には**本文**が出る。サーバーに入っているのは「🔒 メッセージ」で、
  `ChatListViewModel.previewFor` が端末で最新の1通を復号し直して差し替えている。
  **サーバーには本文が無いまま、画面には出る。** 狙いどおり

### 確認の途中で見つけたこと — 一覧の更新が投げっぱなしだった

```kotlin
created.set(payload).await()   // メッセージ本体 — 待つ
db.collection(...).set(...)     // 一覧の1行 — 待たない、結果も見ない
```

一覧の更新は送信の完了条件ではないので、**待たないのは正しい**。しかし結果を捨てて
いたため、**規則に弾かれても誰も気づけません**。「送れたのに一覧だけ古い」という形で
静かに壊れます。

まさに今回、それを確かめる手段がここにありませんでした。**待たないまま失敗だけ記録
する**ようにしました（`addOnFailureListener`）。次に規則を変えたとき、ログに出ます。

このプロジェクトには「握り潰しには理由を書く」という規律があり、テストで検査して
います。ここは `runCatching` を使っていないので検査に掛かりませんでしたが、
**結果を捨てているという意味では同じ**でした。
