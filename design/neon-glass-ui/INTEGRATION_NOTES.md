## 判断が必要な論点（4つ）

実装前に、少なくとも次の4つは決めておく必要がある。
どれも技術的な細部ではなく、**製品の見た目と手触りの方向を決める**問いである。

### 1. ライト先行という決定と、ネオンガラスは噛み合うか

**これが最大の論点。**

Echo は [PRODUCT_VISION.md](../../docs/PRODUCT_VISION.md) の方針としてライトを主設計に選び、
暖かい紙のような背景（`#FBF9F7`）に、アクセント色を**あえて希少に**使う設計にしてある。
アクセントが希少だからこそ、アクセントが出た瞬間に意味が生まれ、触覚と一致させられる。

NEON GLASS は暗い背景に光が乗ることを前提とした表現である。
README も基準色の例として `Color.rgb(6, 11, 26)`（ほぼ黒紺）を挙げている。

したがって、素直に組み合わせると次のどちらかになる。

| 選択 | 意味 |
|---|---|
| **A. ダーク主設計へ切り替える** | ガラスが最も映える。ただしライト先行の決定を覆すことになる |
| **B. ライトのままガラスを使う** | 明るい下地でのガラス表現は別途詰める必要がある。未検証 |
| **C. 部分的に使う** | 暗い面（リアクションピッカー、スタンプパネル、モーダル）だけガラスにする |

**C が最も現実的**に見えるが、これは「見た目の統一感」を捨てる判断でもある。
**開発者本人が決めるべき論点であり、こちらで勝手に選ばない。**

### 2. View ベースと Compose の接続

NEON GLASS は `Drawable` と `View` で書かれている。Echo は全面 Jetpack Compose である。

Compose から使うには `AndroidView` で包むことになるが、
**これをメッセージバブル1つ1つに適用してはいけない。**
`LazyColumn` の各行に View を生成することになり、リサイクルとインタロップのコストが
スクロールに直撃する。Echo の中心価値がスクロールの滑らかさである以上、これは本末転倒になる。

現実的な適用先は、**数が少なく、生存期間が長い大きな面**に限られる。

```
✅  背景（LiquidBackdropView）
✅  コンポーザーのバー
✅  トップバー
✅  スタンプパネル
✅  リアクションピッカーのピル
✅  設定画面のカード

❌  メッセージバブル（数百個、スクロールする）
❌  リアクションチップ（小さい。§4も参照）
```

将来的に AGSL シェーダーを Compose の `RenderEffect` / `ShaderBrush` へ移植する道もあるが、
**それは移植であって組み込みではない。** 別作業として見積もる。

### 3. minSdk の不一致

| | 値 |
|---|---|
| Echo の現在の minSdk | **24**（Android 7.0） |
| NEON GLASS の要求 | **29**（Android 10）以上 |
| 屈折が効く条件 | **33**（Android 13）以上 + ハードウェア描画 |

選択肢:

- **minSdk を 29 へ上げる** — 2026年時点で実害はほぼ無い。ただし「Android 7 以上で使える」という
  現在の決定を変えることになる
- **24 のまま、29 未満ではガラスを使わない** — クラスは `@RequiresApi` で守られているので技術的には可能。
  ただし**端末によって見た目が根本的に違う**製品になる

なお API 33 未満では屈折が消えて塗りへ退避する（クラッシュはしない）。
つまり **29〜32 の端末では「ガラスに見えないガラス」**になる。
デザイン言語として成立するかは実機で見て判断すること。

### 4. GPU 予算と、この製品の中心価値

README にある実測値:

> NEON INSTINCT では中央値 9ms（120Hz の1フレームは 8.3ms）

**すでに 120Hz の予算を超えている。**
NEON INSTINCT はゲームであり、その代償を払う価値がある。

Echo の合格条件には「スクロールが指に貼りついて感じられる」が入っている。
**ここを削ってまで見た目を取る判断は、この製品の前提と矛盾する。**

したがって組み込むなら、**先に測ってから決める**。

```bash
adb shell dumpsys gfxinfo jp.echo.android.debug reset
# 8秒ほどスクロールする
adb shell dumpsys gfxinfo jp.echo.android.debug | grep -E "Janky|gpu percentile"
```

Pixel 10 は 120Hz なので、フレーム予算は 8.3ms。
**ガラスを入れる前と後で測り、差を見る。** 悪化したら面を減らす。

## 組み込むときの手順（決定後に実行）

1. パッケージ名を `com.neonglass` → `jp.echo.android.glass` へ置換し、ディレクトリを移動
2. `:core:glass` モジュールを作る（`androidx.annotation` のみ依存）
3. `LiquidBackdropView` を Compose の最背面に `AndroidView` で敷き、`NeonGlassScene.setBaseColor` を渡す
4. **`NeonGlassTuning.Preset.QUIET` から始める** — README が明示的にメッセンジャー向けに推奨している。
   文字を読む時間が長いアプリでは `SHEEN` と `BLOOM` を下げたほうが読みやすい
5. 適用先を §2 の ✅ に限定する
6. GPU を測る（§4）

## 落とし穴（README より、Echo に効くもの）

- **小さい面では屈折が効かない**（短辺 72px 未満）。リアクションチップは対象外
- **包む View を足して見た目を作らない。** 元の View を制御するコードが包んだ側に届かず、
  「要素は消えたのに面だけ残る」事故が NEON INSTINCT で2回起きている
- `NeonGlassScene` はプロセス全体で1つ。背景を持たない画面ではガラスが塗りへ退避する
- 調整値を変えたら `invalidate()` を木全体へ流す必要がある
