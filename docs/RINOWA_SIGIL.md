# Rinowa Security System — Sigil v1

**Rinowa の封の仕組みの名前。** 本文・写真・動画・通話・バックアップを、
送る端末と受け取る端末の間だけで読める形にする一式を指す。

読みは **シジル**。sigil は「封印の紋章」で、**1つ1つに刻むもの**を意味する。
Rinowa はメッセージ1通ごとに封をする（`data/MessageEnvelope.kt`）ので、
盾や結界のような「境界の内側は安全」という比喩ではなく、この語を選んだ。
**E2EE に安全地帯は無い。** サーバーの中も外も同じく信用しない。

**この文書が適用範囲の正本。** 迷ったらここを見る。

---

## 中身

独自暗号は設計していない。既存の検証済みプロトコルをそのまま使う。

| | |
| --- | --- |
| 方式 | Matrix の **Olm / Megolm**（`org.matrix.rustcomponents:crypto-android` 26.1.4） |
| 鍵交換 | Olm（X3DH + Double Ratchet） |
| 本文 | Megolm（AES-256 + Ed25519 署名） |
| メディア | Tink **AES-GCM-HKDF-STREAMING**。ファイルごとの乱数鍵、鍵は封筒の中 |
| 通話 | SDP と ICE を封筒に入れて渡す |
| バックアップ | 端末側で暗号化してから Google ドライブへ。鍵は利用者の暗証番号から導出 |
| 研究記録 | [RESEARCH_E2EE.md](RESEARCH_E2EE.md) |

## 適用範囲

**この表が約束のすべて。** ここに無いものは守られていない。

| 対象 | SIGIL | 備考 |
| --- | --- | --- |
| 1対1のメッセージ | **○** | |
| グループのメッセージ | **○** | 上限100人（`firestore.rules`）。**全グループが対象** |
| 写真・動画 | **○** | サムネイルも封筒の中。サーバー運用者にも読めない |
| スタンプ | **○** | ID を封筒に入れる。画像そのものは端末が持つ |
| 音声・ビデオ通話 | **○** | SDP / ICE を封筒に入れる |
| 通話の記録（スレッドの1行） | **○** | 0.19.1 から。それ以前は発信者の端末にしか復号できなかった |
| バックアップ | **○** | 暗証番号を忘れると**二度と開けない**。復旧手段は作らない |
| 会話の題名 | **✕** | Firestore に平文で入る |
| 誰と誰が、いつ話したか | **✕** | Firestore から見える。**隠していない** |
| 既読の位置 | **✕** | |

### 守っていないものを、守っているように書かない

**「誰と誰がいつ話したか」はサーバーから見える。** これは E2EE 一般の性質で、
Rinowa も例外ではない。SIGIL は**中身**を守る仕組みであって、**関係**を隠す仕組みではない。

## 前方秘匿性

**鍵は前へ進み、戻らない。** ただし程度を正確に書く。

| | |
| --- | --- |
| Olm（鍵の受け渡し） | Double Ratchet。**完全な前方秘匿性** |
| Megolm（本文） | 前へ進むが、**セッション鍵が漏れるとその時点以降の同一セッション内は読める** |
| Megolm の更新 | **7日** または **100通**（`CryptoEngine.kt`） |

つまり最悪の場合でも、1つのセッション鍵で読めるのは**7日ぶんか100通ぶんまで**。
それより前には戻れない。

比較のため書いておくと、**LINE のレターシーリングは前方秘匿性を白書に記載していない**。
鍵ペアは静的で、再インストールか機種変更まで同じものを使う
（[LINE Encryption Overview v2.2](https://www.lycorp.co.jp/en/privacy-security/line-encryption-whitepaper-ver2.2.pdf)）。

## 鍵の検証（0.20.1 / 2026-08-26 時点）

**「サーバーに本文が無い」に加えて、「相手が本人か、確かめたい人は確かめられる」まで来た。**

会話の名前をタップすると開く。

| | 状態 |
| --- | --- |
| 自分と相手の指紋を見せる | **あり**（4文字区切り・等幅） |
| 相手の端末を全部並べる | **あり**（消去前の登録も隠さない） |
| 鍵が変わったら知らせる | **あり**（実機未検証） |
| 確かめた印を残す | **あり**（この端末の中だけ。取り消せる） |
| クロスサイニング | **無い** |

**ここまでで LINE と並んだ。** LINE も指紋の目視照合までで、それ以上は無い
（技術白書 v2.2）。

### まだ言えないこと

`onlyAllowTrustedDevices = false` のまま。未検証の端末にも鍵を配る。
倒すにはクロスサイニング（V-4）が要る。理由は ROADMAP の「V-4 を今やらない理由」。

**「管理者にも絶対に読めない」と外向きに言うのは、V-4 のあと。**
いま言えるのは「サーバーに本文が無い」と「確かめる手段がある」まで。

## 名前の使い方

- **保証の言葉として使わない。** 「SIGIL で守られています」ではなく、
  「SIGIL の対象です」と書く。範囲は上の表がすべて
- 対象外のものに付けない。会話の題名に SIGIL の印は出さない
- **範囲が変わったら、この表を先に直す。** 実装を先に変えて表を後回しにしない
