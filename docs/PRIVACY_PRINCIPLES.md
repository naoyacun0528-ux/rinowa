# PRIVACY PRINCIPLES

このドキュメントは、この製品において**最も優先度が高い制約**を定義する。
他のすべての設計判断は、この文書に従属する。

---

## 第1原則

> **メッセージ本文を、メッセージ配信以外の目的に使用しない。**

メッセージ本文は、送信者から受信者へ届けるためだけに存在する。
それ以外のいかなる目的（分析、デバッグ、改善、品質向上、不具合調査、AI 学習）にも使用しない。

---

## 絶対禁止事項

以下は **実装しない**。例外はない。

- ❌ 管理者によるメッセージ本文閲覧
- ❌ 管理画面からチャット本文を参照する機能
- ❌ Firebase Console 以外に本文を複製する分析システム
- ❌ Analytics への本文送信
- ❌ Crashlytics ログへの本文混入
- ❌ AI 分析用サーバーへの本文転送
- ❌ デバッグログへの本文出力
- ❌ 通知診断等を理由とした本文の保存

### この制約は開発の都合で緩めない

過去に「デバッグのため管理画面からメッセージ本文を見られる構造」を検討したが、
**この案は完全に撤回された。**

**Claude Code 自身がデバッグしやすいという理由でも、この制約を緩めてはならない。**

不具合調査で本文が見たくなる状況は必ず発生する。そのときの正しい対応は次の通り。

| 状況 | ❌ 誤った対応 | ✅ 正しい対応 |
|---|---|---|
| 送信失敗の原因が知りたい | 本文をログに出す | 失敗理由コード・文字数・添付種別・リトライ回数を記録する |
| 表示崩れが再現しない | 本文をサーバーに保存する | ユーザーにスクリーンショットの提供を依頼する（本人の明示的な操作） |
| 特定の文字で落ちる | 本文を Crashlytics に添付する | 文字クラス（絵文字/CJK/RTL/サロゲートペア）のフラグだけ記録する |
| 通知が届かない | 通知本文を保存する | 通知の配信状態（送信・受信・表示）だけを記録する |

**「一時的に」「開発中だけ」「自分のアカウントだけ」も認めない。**
一時的な仕組みは残る。開発中の仕組みは本番に紛れ込む。

## 型による強制（Enforcement by construction）

規約は破られる。**コンパイラは破られない。**

`:core:analytics` モジュールの公開 API では、イベントパラメータの値として
以下の型 **のみ** を受け付ける。

- `Int`
- `Long`
- `Double`
- `Boolean`
- 事前定義された `enum`（`AttachmentType`, `ConversationType` など）

**`String` を受け付けるオーバーロードは存在しない。**

結果として、次のコードは **コンパイルが通らない**。

```kotlin
analytics.log(MessageSent(body = message.text))   // ← コンパイルエラー。String は渡せない
analytics.log(MessageSent(characterCount = message.text.length))  // ← OK
```

文字数はクライアントで計算し、数値だけを送る。

```
character_count: 24        ✅
message_body: "こんにちは"   ❌ そもそも表現できない
```

### 追加の防御層

1. **型** — `String` パラメータが存在しない（上記）
2. **Lint** — 本文を保持するドメイン型が analytics モジュールへ渡ることを検出するカスタム Lint ルール（Prototype 1 で追加）
3. **ログ** — `MessageText` 型の `toString()` を常に `MessageText(len=24)` にオーバーライドし、
   うっかり文字列連結でログへ出しても本文が出ないようにする
4. **レビュー** — analytics / logging に触れる変更は、この文書との照合を必須とする

## 初期 β における暗号化

友人限定の初期プロトタイプでは、本格的な E2EE をまだ必須としない。

ただしこれは、

> ❌ 「E2EE がないから管理者が本文を閲覧してよい」

という意味では **断じてない**。

初期段階の要件:

- メッセージデータは、**メッセージ配信に必要なバックエンドにのみ**保存する
- **管理用 UI へ本文を露出させない**
- 転送は常に TLS
- Firestore Security Rules により、会話の参加者以外は本文を読めない
- 開発者アカウントに本文への特権的な読み取り経路を作らない

### 本格的な公開前

- E2EE 方式を検討する
- **独自暗号方式は設計しない**
- 既存の十分に検証されたプロトコル・ライブラリのみを候補とする
  （例: Signal Protocol / libsignal, MLS (RFC 9420) など）
- 暗号化実装フェーズでは、**別途セキュリティレビューを行う**

## 収集してよいもの

本文ではなく、**利用状況のメタデータ**のみを収集する。

**目的は監視ではない。**
UI 改善 / 操作改善 / 触覚改善 / パフォーマンス改善 / 実際に使われている機能の把握 / バグ検出、が目的である。

詳細な定義は [ANALYTICS_SCHEMA.md](ANALYTICS_SCHEMA.md) にある。

### 収集しないもの（メタデータであっても）

- 会話 ID / メッセージ ID
  → 社会グラフ（誰と誰がどれだけ話しているか）が復元できてしまう
- 表示名 / メールアドレス / 電話番号 / 連絡先
- 選択された絵文字そのもの（パレット内の index のみ）
- 下書きテキスト / 添付ファイル名
- 精密な位置情報
- 広告 ID（`google_analytics_adid_collection_enabled = false`）

### 集計優先

公開段階では、可能な限り**個別ユーザー単位ではなく集計データ**を中心にする。
Developer Console は個人を特定・追跡できる粒度のビューを持たない。

## Privacy UI

設定画面に `Privacy → Analytics Data` を設け、**利用者本人が何を収集されているか確認できる**ようにする。

```
Messages                 NEVER COLLECTED
Message length           Collected
Usage duration           Collected
Feature interactions     Collected
Crash diagnostics        Collected
```

- 各項目をタップすると、具体的に何が送られるかの実例を表示する
- Analytics の ON / OFF をユーザー自身が変更できる構造とする
- OFF にしても機能制限は一切かけない

---

## Developer Console

開発者向け管理画面を作る。ただし **メッセージ本文は絶対に表示しない。**

表示するのは集計値のみ（DAU、送信数、文字数合計、平均セッション、クラッシュ率、
スワイプ返信の完了率、触覚 ON 率など）。

**本文を表示する画面は、非表示・権限制限・要認証のいずれであっても作らない。**
「作ったが権限で隠している」も禁止する。存在させない。
