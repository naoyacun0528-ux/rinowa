## 0. 結論

| 問い | 答え |
|---|---|
| 専用の SDK が要るか | **要りません。** 衛星は普通の携帯回線として見えます |
| では何をすればいいのか | **衛星だと気づいて、振る舞いを変えること。** それだけが仕事です |
| 気づけるのか | **Android 15 以降なら気づけます。** それ以前は判定不能として扱います |
| Firestore は動くか | **動かないと考えるべきです。** 別経路が要ります（§4） |
| Yosegi は役に立つか | **ここが Yosegi の本当の使い所です。** 240 B と 43 B の差が通るか通らないかを分けます |

> **衛星対応とは「衛星用の機能を足すこと」ではなく、
> 「衛星のときに、余計なことを全部やめること」です。**

## 1. Starlink Direct とは何で、何ではないか

**Direct to Cell** は、**改造していない普通のスマートフォン**が衛星と直接つながる仕組みです。
日本では KDDI の **au Starlink Direct**。

技術的には、衛星が LTE の基地局として振る舞います。したがって:

- **アプリから見ると、ただの携帯回線です。** ソケットは普通に開きます
- **専用 API は要りません。** 通信部分を書き換える必要はありません

**しかし、性能はまったく違います。**

| | 通常の 4G/5G | **Direct to Cell** |
|---|---|---|
| 帯域 | 数十 Mbps | **衛星の footprint 全体で数 Mbps を分け合う** |
| 1端末あたり | — | **キロビット単位** |
| 遅延 | 数十 ms | **桁が上がる** |
| 安定性 | 高い | 衛星が動くので断続的 |

**「遅い 4G」ではありません。「たまにしか通らない細い管」です。**
この違いを設計に反映しないアプリは、動作が遅くなるのではなく**何も届きません**。

## 2. 衛星だと、どう気づくか

`NetworkCapabilities.NET_CAPABILITY_NOT_BANDWIDTH_CONSTRAINED`（Android 15 で追加）。

**「制約されていない」という肯定形の能力**なので、**無いこと**が制約を意味します。
衛星リンクはこれを持ちません。

実装は `android/app/.../data/LinkClass.kt`。

```
Normal       通常の Wi-Fi / 携帯
Constrained  衛星、または極端に細い回線
Offline      使える網が無い
Unknown      この Android では判定できない
```

### Android 15 未満をどうするか

**`Unknown` を `Normal` として扱います。** 憶測で細いと決めつけません。

理由: 判定できないことを理由に写真を止めると、**普通に動いている回線を勝手に制限する**ことになります。
逆向きの失敗（細い回線に写真を出してしまう）より、こちらのほうが害が大きい。

これは Direct で2回踏んだ教訓と同じ形です
——**API level ≠ 端末の能力。観測できない能力を仮定しない。**

## 3. 衛星のときに何をやめるか

**やめることのほうが、やることより多い。** それが設計の中身です。

| 機能 | 通常 | **衛星** | なぜ |
|---|---|---|---|
| テキスト | ○ | **○（本体）** | これだけは必ず通す |
| 写真の送信 | ○ | **×** | 66 KB は数十秒〜数分ぶんの帯域 |
| 写真の受信 | ○ | **×（サムネイルのみ）** | サムネイルは既にメッセージの中にある |
| スタンプの取得 | ○ | **×** | 持っている物だけ表示 |
| プロフィール画像 | ○ | **×** | 名前で足りる |
| **既読** | ○ | **×** | **1通読むたびに1書き込み。本文と同じ費用を「見たよ」に使う** |
| 在席表示 | ○ | × | 常時更新は論外 |
| 本文の長さ | 4000字 | **500字** | 上限で守る |
| 形式 | 通常 | **Yosegi + 辞書** | §5 |

`LinkClassifier.policy()` が1か所にまとめています。
**散らばった `if` にしないのは、1つ忘れた prefetch が、
テキストが通るはずだった帯域を食い潰すからです。**

## 4. Firestore は衛星で動かないと考える

**これが最も重要な設計上の判断です。**

Firestore のクライアントは gRPC の**長時間接続**を張ります。
往復が長く断続的な回線では、**接続の確立自体が終わりません**。
遅くなるのではなく、**何も起きない**。

### したがって、衛星用の細い経路が要ります

```
通常:   アプリ → Firestore（gRPC 常時接続）
衛星:   アプリ → Yosegi + 辞書圧縮 → HTTPS POST 1回 → 自前サーバー → Firestore
```

- **1回の POST で終わる。** 接続を維持しない
- **本文は 43 バイト前後**（Yosegi + 8 KB 辞書、実測 `RESEARCH_WIRE_FORMAT.md`）
- **認証は `push.php` と同じ**。Firebase の ID トークンをヘッダで検証する
- 受信は**ポーリング**。常時接続を張れない以上、これしかない

サーバー側は `server/lifeline.php`（未実装）。`push.php` の骨格をそのまま使えます。

### ここで Yosegi が効く

これまで Yosegi の使い所は Direct と Mesh でしたが、**衛星が3つ目で、いちばん切実です。**

| 形式 | 1通 | キロビット級の回線で |
|---|---|---|
| JSON | 267 B | 重い |
| Yosegi | 98 B | |
| **Yosegi + 辞書** | **43 B** | **通る** |

**同じ帯域で6倍の通数が入ります。**
`YOSEGI_V1_SPEC.md` を凍結しておいたのは、こういう経路のためです。

## 5. 何を約束しないか

- **衛星でビデオ通話はできません。** 音声通話もできません。**帯域が3桁足りない**
- **衛星で写真は送れません。** サムネイルは既に届いているので見えますが、本体は届きません
- **リアルタイムではありません。** 送信が数十秒かかることがあります
- **キャリアと契約に依存します。** au Starlink Direct は対応端末・対応プランが要ります

**「衛星対応」と書いて、通話ができると誤解されるのが最悪です。**
画面には**できることだけ**を出します。

---

## 6. 画面での見せ方

**細い回線であることを、隠さずに、しかし邪魔にならない形で出します。**

- 会話画面の上に細い帯:「**衛星接続 — テキストのみ**」
- 写真ボタンは**押せるが、押すと理由が出る**。消すと壊れたように見える
- 送信中の表示を長めに許容する。数十秒かかるのは異常ではない
- **既読が付かないことを説明する。** 何も言わないと「無視された」と読まれる

最後のものが特に重要です。**既読を止めるという判断は、
説明しなければ人間関係の誤解になります。**
