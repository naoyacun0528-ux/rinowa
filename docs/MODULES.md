# モジュールの分け方

## なぜ分けるのか — ビルド時間ではない

先に測った数字を置いておく（Snapdragon X · 32,506行時点）。

| やったこと | 時間 |
|---|---|
| 何も触らずビルド（Gradle の固定費） | 2.30 秒 |
| 画面を1つ書き換えてビルド | 2.50 秒 |
| 全部消してゼロから | 8.07 秒 |

**差分ビルドの実質的な作業は 0.2秒。** 残りは Gradle が起動して
「何も変わっていない」と確認するだけの固定費で、モジュールを増やすと
この固定費のほうが増える。実際 `:core:model` を切ったあとは
2.50秒 → **2.65秒** になった。

だから分ける理由は速さではない。**依存の向きをコンパイラに守らせること。**

同じモジュールの中では、`data` が `ui` を参照しても誰も止めない。
規約は人が守るもので、人は忘れる。モジュールの境界は忘れない。


放っておいていい。**上の5組が本物。**

## 段取り

### 済み — `:core:model`（493行）

外への依存は `@Immutable` と `ImmutableList` だけ。逆に 33ファイルが
ここを参照している。**完全な葉**なので、切るのに何の準備も要らなかった。

切った時点で1つ見つかった。`MessageRow` が `message.content` を `is` で
判定してスマートキャストに頼っていた箇所が、別モジュールになった途端に
コンパイルを通らなくなった。別モジュールのプロパティは読むたびに同じものを
返すと保証できないため。**境界を引いたから見えた穴。**

### 次 — `:core:crypto`（1,177行）

`crypto ⇄ data` が1本ずつ。`data` 側が `CryptoTransport` を呼び、
`crypto` 側が `data` の何かを1つ参照している。**その1つを model か
インタフェースに落とせば切れる。** 5組の中で一番浅い。

切ると得られるもの: 暗号の層が Firestore を知らないことが、
コンパイラで保証される。`docs/RINOWA_SIGIL.md` が言葉で約束していることの、
機械が読める版。

### そのあと — `:feature:calls`（2,748 + ui/calls 904 = 3,652行）

`calls ⇄ data` と `calls ⇄ notifications` の2組を先に切る。
通話は「着信を鳴らす」ために notifications を呼び、notifications は
「今の通話状態」を知るために calls を呼んでいる。片方を**イベントの
受け渡し**（`calls` が状態を publish し、`notifications` が購読する）に
変えれば一方向になる。

`:app` から 3,652行が抜けるので、ここが一番効く。

### そのあと — `:feature:backup`（814 + 581 = 1,395行）

`backup ⇄ data` は4本と3本で、5組の中では一番太い。
`backup` は保存するために会話を読み、`data` は復元されたものを書き戻す。
**読む側と書く側を分ける**（`backup` は読み取り専用のインタフェースだけ
知る）のが素直な形。

### 保留 — `ui/*` の分割

`ui/chat` は 5,398行で一番大きいが、**今は切らない。**

`ui/*` の相互参照は `ui/RinowaApp.kt`（画面の切り替え役）を経由するもので、
これを切るには画面遷移の仕組みごと入れ替えることになる。得られるものが
「`:app` が薄くなる」だけなら、今はやらない理由のほうが強い。

`:feature:calls` と `:feature:backup` を切った経験を踏まえてから決める。

## 守ること

1. **`:core:*` は Android の外の世界を知らない。**
   Firebase も、画面も、通話も入れない。入れた瞬間に下の層が上の層を知る。

2. **`:feature:*` は互いを参照しない。**
   通話が backup を呼びたくなったら、それは `:core` に置くべきものが
   feature に紛れているということ。

3. **1つ切るたびに測る。**
   ビルド時間が伸びたら伸びたと書く。分けたこと自体を成果にしない。
