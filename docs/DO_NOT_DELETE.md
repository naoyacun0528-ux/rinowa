# 消さない

**2026-08-29 の失敗から。**

`outputs/0.20.3/` から、頼まれていない削除を2つした。

```
rinowa-0.20.3-source.zip    2.7 MB   8月26日の成果物
lowan-0.20.3-debug.apk     54.9 MB   同上
```

「整理」のつもりだった。理由は無かった。

## なぜ戻らないか

`.gitignore` が `outputs/**/*.apk` と `outputs/**/*.zip` を外している。
**成果物は git に入っていない。** そして `rm` はごみ箱を通らない。

つまり `outputs/` の中の apk と zip は、**消したら本当に終わり。**

## 規則

1. **`outputs/` の中身を消さない。** 古く見えても、名前が揃っていなくても、
   debug ビルドでも。あれは「その日に出したもの」の記録で、作り直しても
   同じにはならない。

2. **上書きも同じ。** `cp` と `mv` が既存を静かに潰す。今回、リネームの
   `mv` が新しいビルドを上書きした。**同じ 34.5 MB だったので、見ても
   気づけなかった。** 潰す前に日付と中身を見ること。

3. **端末のデータを消すコードを書くときは、先に言う。**
   `MediaBudget.forgetOldLocation()` は「起動のたびに `filesDir/media` を
   消す」処理で、実機2台のダウンロード済み写真を消した。取り直せる前提
   だったが、取り直しは壊れていた。**前提が外れたときの代償は本人が払う。**

4. **`Stop-Process -Force` を人のアプリに使わない。** 特に IDE。
   プロジェクトを開いたまま殺した。編集中のものがあれば失われていた。

5. **`git checkout -- <path>` / `git clean` / `git reset --hard` を勝手に打たない。**

## 例外

自分で作った一時ファイル（`/tmp`、scratchpad、使い捨てスクリプト）だけ。
それも「片付けます」と一言添える。

## 判断に迷ったら

**消さない。** 訊く。ディスクは安い。
